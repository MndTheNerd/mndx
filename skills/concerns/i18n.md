# Internationalization checklist

- [ ] No hard-coded user-facing strings. Everything goes through the i18n layer (next-intl / i18next /
      react-i18next / expo-localization) from the first feature, even with one language.
- [ ] ICU message format for plurals, gender and variables. No string concatenation for sentences.
- [ ] **RTL** (Arabic, Hebrew, Persian, Urdu): `dir="rtl"` / `I18nManager`, logical CSS properties
      (`margin-inline-start`, not `margin-left`), mirrored directional icons, and layouts tested in RTL.
- [ ] Dates, times, numbers and currencies formatted with `Intl` for the user's locale. Times stored in UTC and
      shown in the user's time zone.
- [ ] Fonts support every target script (Arabic needs a proper Arabic face, not a fallback).
- [ ] Text expansion: layouts survive about 35% longer strings (German) and very short ones. No fixed-width
      buttons with text.
- [ ] Locale detection with a manual switch that persists. Locale-aware URLs for public web pages (SEO hreflang).
- [ ] Input: names, addresses and phone numbers allow international formats (E.164 for phones). No "first/last
      name required" assumptions.
- [ ] Verify: screenshots of the main flow in each target locale, including one RTL locale if targeted.
